# Tesla 行车记录仪查看器（中文版）

一款完全运行在本地的 Tesla 行车记录仪视频查看工具。**无需联网、无需后端服务器**，打开一个 HTML 文件即可使用。

基于开源项目 [NateMccomb/TeslaCamViewer](https://github.com/NateMccomb/TeslaCamViewer) 的核心思路进行重写与本土化适配，全部界面文案、交互逻辑、文件识别都做了中文适配与精简。

---

## 功能特性

- ✅ **零依赖** — 单个 `index.html` 文件，双击即可在浏览器打开
- ✅ **零上传** — 所有视频文件只在你的电脑里播放，不会上传到任何服务器
- ✅ **多路同步播放** — 同时播放前 / 后 / 左后视 / 右后视 4 个摄像头画面，时间轴同步
- ✅ **自动识别录制类型** — 区分手动保存事件、哨兵事件、最近录制循环
- ✅ **按日期 / 按事件浏览** — 支持单独查看手动事件、哨兵事件或最近录制
- ✅ **5 种布局** — 前 + 后、左 + 右、4 路网格、画中画、单画面（聚焦前摄像头）
- ✅ **键盘快捷键** — `Space` 播放暂停、`←/→` 切换段、`L` 切换布局、`S` 切换速度等
- ✅ **逐段连续播放** — 一段播完自动跳下一段
- ✅ **可调播放速度** — 0.25× / 0.5× / 1× / 1.5× / 2× 5 档
- ✅ **节选剪辑 + 导出视频** — 设定入点 / 出点，把选中的片段导出为 MP4 文件（支持跨段合并、多路合成、烧录时间水印）
- ✅ **响应式中文 UI** — 暗色 Tesla 风格，全中文界面

## 使用方法

### 方法一：直接打开（最简单）

直接双击 `index.html`，浏览器会自动打开该页面。然后：

1. 点击右上角 **"选择 TeslaCam 文件夹"** 按钮。
2. 在弹出的文件选择对话框中，定位到你的 U 盘，进入 `TeslaCam` 文件夹并确认。
3. 应用开始扫描视频文件，扫描完成后会自动播放最新的视频。

> **要求**：使用 Chrome、Edge 或其它基于 Chromium 的浏览器（FireFox / Safari 在 `file://` 协议下支持有限）。

### 方法二：本地 HTTP 服务（推荐 / 体验更完整）

为了支持 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_Access_API)（可记忆上次选择的文件夹，体验更接近原生 App），你也可以起一个本地 HTTP 服务：

- **Windows**：双击 `启动本地服务.bat`
- **macOS / Linux**：在终端中运行 `python3 -m http.server 8000`，然后访问 <http://localhost:8000>

启动脚本仅在本机启动服务，**不会对外暴露任何端口**。

## 节选剪辑与导出（v2 新增）

可以把一段（或跨越多段）视频里的**指定时间段**裁剪出来，导出成一个独立的视频文件。
全程在本机浏览器内完成，不联网、不上传、不依赖 ffmpeg 等外部工具。

### 第一步：设定裁剪区间（入点 / 出点）

先选中并播放要剪辑的那一段视频，然后**任意一种方式**都能设定：

| 方式 | 操作 |
|---|---|
| 快捷键（最顺手） | 播放到想要的位置，按 `I` 标记**起点**，继续播放到结束位置，按 `O` 标记**终点** |
| 控件按钮 | 点播放控制条上的 **`⇤ 入点`** / **`出点 ⇥`** |
| 拖拽手柄 | 进度条上出现蓝色区间条后，直接拖动两端的**蓝色手柄**精调 |
| 数值输入 | 打开剪辑面板，在「起点 / 终点」输入框中填写秒数（如 `12.5`），旁有 `−1s / −0.1 / +0.1 / +1s` 微调按钮 |

设定好之后：

- 进度条上会出现**蓝色高亮区间**，直观显示将被保留的部分；
- 面板中实时显示**选区时长**；
- 按 `P`（或点「预览选区」）可以只播放这段区间，到出点会自动暂停，方便确认。

> 选区参数会被自动校正：超出视频范围会被夹到 `0 ~ 总时长`，起点晚于终点时会自动交换顺序。

### 第二步：加入剪辑列表

确认无误后，按 `C` 打开**剪辑面板**（从右侧滑出，**不会遮挡视频画面**，可以边看边调），点击 **「＋ 把当前选区加入列表」**。

- 会看到该条目的**时间、起止位置、时长**；
- 想保留多个片段，就切换到**其它视频段**重复上面的步骤继续追加 —— 导出时会**按顺序拼接成一个文件**；
- 每条右侧的 `✕` 可以单独移除；列表上限 50 项。

### 第三步：设置导出参数并导出

| 选项 | 说明 |
|---|---|
| **画面布局** | 可单独指定导出用布局（默认"跟随当前布局"）。四路布局会把 4 个摄像头合成到同一个画面里 |
| **输出画质** | `1080p`（默认）/ `720p` / `1440p` / `源分辨率`。面板下方会**实时显示预计输出分辨率** |
| **帧率** | 30 / 25 / 24 / 15 fps |
| **文件格式** | `自动（优先 MP4）` / `MP4 (H.264)` / `WebM (VP9)`。Chrome / Edge 下默认导出 **MP4**，格式不可用时自动回退 |
| **导出速度** | `1× 实时`（推荐，不丢帧）/ `2×` / `4×`（更快但会丢帧，画面运动剧烈时不建议） |
| **烧录时间水印** | 勾选后，`YYYY-MM-DD HH:mm:ss` 时间戳会被**永久烧进**画面右上角（与预览时看到的一致） |

点击 **「开始导出」**，底部显示进度百分比、已录制时长与预计剩余时间。导出完成后浏览器会**自动下载**文件，文件名形如：

```
TeslaCam_20260912_143000_0.6s-3.0s.mp4        ← 单个片段
TeslaCam_20260912_143000_2clips_3s.mp4        ← 多个片段合并
```

导出过程中可以点 **「停止并保存」** 提前结束，已经录到的部分仍会保存下来。

### 关于导出，有几点需要了解

1. **导出是"实时录制"的** —— 基于浏览器 `MediaRecorder`，`1×` 速度下 1 分钟的片段大约需要 1 分钟。这是浏览器端纯前端方案的固有代价（无法像 ffmpeg 那样离线极速转码）。
2. **导出期间请保持本标签页在前台**。切到后台会被浏览器降频，导致耗时变长或掉帧。
3. **画面经过一次重新编码**，严格来说会有轻微画质损失（不是无损切割）。如果必须无损，需要用 `ffmpeg -c copy` 之类的工具直接切原始文件。
4. **音频**：TeslaCam 视频本身不含音轨，导出的文件同样没有音轨。
5. **画面构图**：导出画面来自 `canvas` 合成 —— 单画面模式输出单路全屏；四路模式输出 2×2 网格；画中画模式输出主画面 + 右下角小窗。某路摄像头缺失时，对应格子为黑屏。

## 支持的 TeslaCam 文件夹结构

应用会自动识别以下标准 Tesla 录制目录结构：

```
TeslaCam/
├── RecentClips/                       ← 最近录制（循环覆盖约 1 小时）
│   ├── 2026-09-12_14-30-00-front.mp4
│   ├── 2026-09-12_14-30-00-back.mp4
│   ├── 2026-09-12_14-30-00-left_repeater.mp4
│   ├── 2026-09-12_14-30-00-right_repeater.mp4
│   ├── 2026-09-12_14-31-00-front.mp4
│   └── ...
│
├── SavedClips/                        ← 手动保存的事件（喇叭、行驶记录）
│   └── 2026-09-12_14-30-00/
│       ├── event.json
│       ├── thumb.png
│       ├── front.mp4
│       ├── back.mp4
│       └── ...
│
└── SentryClips/                       ← 哨兵模式录制的事件
    └── 2026-09-12_14-30-00/
        ├── event.json
        ├── front.mp4
        └── ...
```

文件名中可识别的摄像头标识：

| 文件名包含的关键字 | 中文显示 |
|---|---|
| `front` | 前摄像头 |
| `back` / `rear` | 后摄像头 |
| `left_repeater` / `left` | 左后视摄像头 |
| `right_repeater` / `right` | 右后视摄像头 |
| `left_pillar` / `right_pillar` | B 柱摄像头（新款 Model S/X） |
| `narrow_front` | 长焦摄像头 |

Tesla 固件早期会把摄像头文件直接命名为 `front.mp4`、`back.mp4`（没有时间戳前缀），应用也能识别：会自动以父目录名作为时间戳。

## 常见问题

**Q：为什么点击"选择文件夹"按钮没有任何反应？**
A：现代浏览器出于安全考虑，要求页面必须由用户手势触发才能弹出文件选择框。请确认你没有在浏览器控制台手工调用了相关 API，直接点击页面上看得见的按钮即可。

**Q：能不能扫描整个 U 盘根目录而不是 TeslaCam 文件夹？**
A：可以，选择 U 盘的根目录即可，应用会自动寻找其中的 `TeslaCam` 子目录。

**Q：能记住上次选择的文件夹吗？**
A：只有在起本地 HTTP 服务（方法二）时才能用浏览器自带的"记住目录"权限。双击直接打开时，每次需要重新选择。

**Q：导出的视频为什么是 MP4 而不是原文件？大小对不上？**
A：导出是**重新编码**后的结果（`canvas` 合成 → `MediaRecorder` 录制），不是原始文件的字节拷贝，所以体积、码率、编码参数都会变化，画质也会有极轻微损失。如果只需要保真的切割，建议用 `ffmpeg -ss ... -to ... -c copy` 直接裁剪原始 MP4。

**Q：导出很慢 / 导出后视频卡顿？**
A：导出采用实时录制，`1×` 速度下耗时约等于片段时长。请：① 保持标签页在前台；② 使用 `1× 实时` 速度档；③ 若选了「源分辨率」+ 四路布局，输出像素很高，建议改用 1080p。

**Q：为什么"选择 TeslaCam 文件夹"之后剪辑列表是空的？**
A：剪辑列表不会自动生成，需要你手动标记区间后点「＋ 把当前选区加入列表」。重新选择文件夹也会清空列表（避免误用旧数据）。

**Q：原版 TeslaCamViewer 的很多高级功能（GPS 地图、AI 车牌识别等）呢？**
A：本工具专注于"回看 + 节选导出"两个核心场景，没有引入外部地图、OCR、AI 模型等（这些通常需要联网或后端服务）。如有需要可以访问 [原项目](https://github.com/NateMccomb/TeslaCamViewer) 使用在线版。

**Q：我的视频特别多，扫描很慢怎么办？**
A：扫描阶段只读取文件名，不会真正解码视频，所以即使有上千段也很快速。如果文件很多（比如几十 GB），第一次进入播放时浏览器需要缓冲几个摄像头的视频，这个等待是正常的。

## 技术说明

- 纯原生 HTML / CSS / JavaScript 实现，无任何第三方库
- 兼容 Chromium 内核浏览器（Chrome 86+ / Edge 86+）；剪辑导出需要支持 `canvas.captureStream()` + `MediaRecorder` 的浏览器（Chrome 86+ / Edge 86+ 均可，MP4 导出需 Chrome 111+）
- 视频使用浏览器原生 `<video>` 元素 + `URL.createObjectURL` 解码本地文件
- 多视频同步播放通过监听主视频的 `timeupdate` / `play` / `pause` 事件驱动
- **剪辑导出**链路：选区时间轴 → 离屏 `<video>` 定位入点 → 逐帧 `drawImage` 合成到 `<canvas>` → `canvas.captureStream(fps)` → `MediaRecorder` 编码 → `Blob` → 自动下载
- 时间水印直接绘制在 `canvas` 上（`fillText` + 半透明底），因此可以永久烧录进导出文件
- 布局高度使用 flex 框架而非 `calc(100vh)`，避免窗口最大化 / 高 DPI 缩放下底部控件被挤出视口
